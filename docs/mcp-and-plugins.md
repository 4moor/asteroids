# Готовые MCP и plugins для практики

Выберите инструмент под конкретную задачу, подключите его и покажите
хотя бы один полезный вызов. В репозитории нет автоматически запускаемых
MCP-серверов; ниже — примеры, которые можно добавить в настройку клиента.

## Playwright MCP: проверить игру в браузере

Этот сервер даёт агенту инструменты управления браузером. Он отличается
от `@playwright/test`: тесты выполняют заранее написанные сценарии,
а через MCP агент выбирает действия во время работы.

Нужны Node.js и браузер. Для воспроизводимого примера закреплена версия
`@playwright/mcp@0.0.82`; перед занятием проверьте её установку.
`--isolated` создаёт отдельный браузерный контекст.

В Codex добавьте в проектный `.codex/config.toml`:

```toml
[mcp_servers.playwright]
command = "npx"
args = ["-y", "@playwright/mcp@0.0.82", "--isolated"]
```

Для Claude Code создайте проектный `.mcp.json`:

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@0.0.82", "--isolated"]
    }
  }
}
```

Запустите `npm run dev`, проверьте подключение через `/mcp` и попросите
агента открыть напечатанный адрес, выбрать миссию, начать полёт и проверить
счётчик жизней. Пусть он укажет, что подтвердил инструментом.
Проверку физики дополняйте модульными тестами: снимок страницы не доказывает
корректность столкновений.

[Документация Playwright MCP](https://playwright.dev/mcp/installation).

## GitHub MCP: разобраться в issue или PR

[Официальный сервер GitHub](https://github.com/github/github-mcp-server)
умеет работать с репозиториями, issues и PR. Начните с чтения задачи,
диффа и обсуждения. Возможности сервера можно ограничить
[режимом только чтения](https://github.com/github/github-mcp-server/blob/main/docs/server-configuration.md).

Авторизация зависит от клиента и аккаунта. Используйте штатный вход;
не вставляйте токены в проектные файлы или сообщения агенту.
Подключение MCP не выдаёт права обходить защиту main.

Задание: найти критерии готовности своего PR, сопоставить их с диффом
и подготовить список недостающих проверок.

## OpenAI Docs MCP: исследовать настройки Codex

Публичный сервер `https://developers.openai.com/mcp` даёт доступ только
к документации. Для Codex можно добавить:

```toml
[mcp_servers.openai_docs]
url = "https://developers.openai.com/mcp"
```

Задание: проверить по документации, откуда загружаются инструкции и skills,
затем сопоставить это с файлами репозитория.

[Документация сервера](https://developers.openai.com/learn/docs-mcp).

## Упаковать workflow в plugin

Выберите один из двух проектных skills и создайте локальный plugin
по документации своего клиента. Проверьте его обнаружение в отдельном
учебном клоне, где нет исходного skill: так будет видно, что работает
именно установленный пакет.

Объясните, какие файлы принадлежат plugin, а какие — настройке проекта.
Если plugin включает MCP, проверьте отдельно загрузку skill и доступность
сервера. Публикация в общий каталог для упражнения не требуется.

Форматы и установка:
[Codex plugins](https://developers.openai.com/plugins/build/plugins),
[Claude Code plugins](https://code.claude.com/docs/en/plugins).
