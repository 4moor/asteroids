# Участие в разработке

Один PR должен решать одну понятную задачу. Для первого вклада удобно
добавить [миссию](docs/missions.md). Новые механики, улучшения управления
и изменения агентских инструкций тоже можно предложить отдельными PR.

## Начало работы

Создайте форк на GitHub. В примере замените YOUR_LOGIN на свой логин.

```sh
git clone https://github.com/YOUR_LOGIN/asteroids.git
cd asteroids
git remote add upstream https://github.com/asteroids-developers/asteroids.git
git fetch upstream
git switch main
git merge --ff-only upstream/main
git switch -c feat/my-mission
npm ci
```

Перед коммитом посмотрите `git status` и `git diff`.
Добавляйте конкретные файлы задачи; личные настройки и результаты запусков
остаются локально.

```sh
npm run check
git diff --check
git add src/missions/presets/my-mission.json
git commit -m "feat: add my mission"
git push -u origin feat/my-mission
```

После push откройте PR с базой `asteroids-developers/asteroids:main`.
В описании укажите поведение и проверки. Для изменённого интерфейса или
механики выполните также `npm run test:e2e`.

## Ревью и слияние

CI обязателен для всех PR. Для студенческих изменений нужно одобрение
@KalininVD; одобрение одногруппника полезно, но не заменяет его.
Новые изменения сбрасывают устаревшее одобрение.

Собственные PR KalininVD могут быть влиты с обходом требования ревью.
Правила проекта разрешают этот обход только для его собственных PR.
CI, актуальность ветки и разрешение обсуждений остаются обязательными.
[Настройки защиты](docs/github-policy.md) описаны отдельно.

При первом PR из форка GitHub может ожидать разрешения преподавателя
на запуск Actions. Проверьте сообщение в PR перед поиском ошибки в коде.

## Если возник конфликт

Находясь в своей рабочей ветке:

```sh
git fetch upstream
git merge upstream/main
git status
```

Откройте конфликтующие файлы и восстановите итоговое поведение с учётом
обеих задач. При работе с агентом попросите объяснить, какие изменения
он сохраняет. Затем выполните проверки, добавьте исправленные файлы
и завершите merge-коммит:

```sh
npm run check
git diff --check
git add PATH_TO_RESOLVED_FILE
git commit
git push
```

Замените PATH_TO_RESOLVED_FILE на путь к исправленному файлу.
Для изменения игрового поведения повторите браузерные проверки.
Команда `git merge --abort` отменяет незавершённое слияние, если нужно
вернуться к состоянию до него. Обычная синхронизация этим способом
не требует force push.

## Заметка о работе с агентом

В шаблоне PR есть короткое поле для семинара. Запишите одно наблюдение:
какую инструкцию, skill или MCP вы использовали, что агент сделал
и как вы проверили результат. Не прикладывайте полные личные конфигурации,
историю диалога или токены.
